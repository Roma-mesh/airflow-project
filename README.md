# **Airflow Rick & Morty Data Pipeline: Сбор и обработка данных вселенной**

[![Apache Airflow](https://img.shields.io/badge/Apache_Airflow-2.7+-darkcyan?logo=apacheairflow)](https://airflow.apache.org)
[![Python](https://img.shields.io/badge/Python-3.8+-blue?logo=python)](https://python.org)
[![PostgreSQL](https://img.shields.io/badge/PostgreSQL-15+-blue?logo=postgresql)](https://postgresql.org)

Проект демонстрирует построение ETL-пайплайна для автоматизированного сбора данных из Rick & Morty API с их последующей загрузкой в аналитическую базу данных.

---

## 🎯 **Цель проекта**

Создать отказоустойчивый ETL-пайплайн, который автоматически собирает, обрабатывает и загружает данные из публичного API Rick and Morty в аналитическую базу данных, обеспечивая их актуальность и готовность для анализа.

---

## 📋 **Задачи**

- [x] **Изучить Apache Airflow** — освоить основные операторы, TaskFlow API и принципы оркестрации.
- [x] **Проанализировать источник данных** — разобраться в структуре, ограничениях и пагинации Rick and Morty API.
- [x] **Спроектировать и реализовать DAG'и** — от простых до сложного ETL-пайплайна с несколькими сущностями.
- [x] **Обеспечить надёжность загрузки** — реализовать обработку ошибок, идемпотентные операции (UPSERT) и механизмы повторных попыток.

---

## 🛠️ **Этапы работы**

### 1. **Анализ и исследование**
- Изучил документацию Rick and Morty API, чтобы понять доступные endpoints, структуру ответов и механизм пагинации.
- Проанализировал требования к данным для аналитики — определил ключевые сущности и связи между ними.
- Освоил основы Apache Airflow 2.0, сравнив классический подход с операторами и современный TaskFlow API.

### 2. **Проектирование и разработка**
- Создал базовые DAG'и для понимания работы сенсоров, операторов и контекста выполнения.
- Разработал DAG для условного выполнения задач и простого сбора данных из API.
- Спроектировал схему БД в PostgreSQL для хранения персонажей, локаций и эпизодов.
- Реализовал полный ETL-пайплайн, который извлекает данные с учётом пагинации, трансформирует JSON в плоскую структуру и выполняет идемпотентную загрузку (UPSERT) в БД.
- Масштабировал решение, использовав `TaskGroup` для параллельной загрузки нескольких сущностей.

### 3. **Внедрение лучших практик**
- Настроил политики повторных попыток с экспоненциальной задержкой для устойчивости к сбоям API.
- Реализовал механизм пагинации в коде, чтобы гарантированно получить все данные.
- Добавил ограничения параллелизма и корректно настроил расписание DAG.

---

## 📈 **Результаты**

✅ **Серия из 6 DAG'ов**, демонстрирующая путь от базового знакомства с Airflow до production-ready пайплайна.  
✅ **Рабочий ETL-процесс**, который ежедневно собирает данные по ~800 персонажам, 100+ локациям и 50+ эпизодам.  
✅ **Аналитическая база данных** в PostgreSQL с нормализованными таблицами, пригодными для выполнения сложных SQL-запросов.  
✅ **Устойчивое решение** с обработкой ошибок, идемпотентной загрузкой и механизмами повторных попыток.

Проект служит шаблоном для построения аналогичных ETL-пайплайнов к другим REST API с пагинацией.
